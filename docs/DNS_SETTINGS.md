# DNS 设置

在「设置」页点击「网络」分区，可以查看 DNS 状态卡片。卡片显示配置来源、最终解析模式、监听地址和上游 DNS。状态按核心是否运行区分，核心未运行时展示的是已生成的配置，读取失败时不会显示为成功状态。

点击「配置 DNS」打开编辑窗口：

- 默认跟随订阅和增强配置。开启全局自定义后，只覆盖修改过的字段，未修改字段继续继承。
- 常用设置提供 DNS 开关、IPv6、解析模式、监听地址、上游、引导和后备 DNS。服务器每行一个地址。
- 高级配置提供节点 DNS、直连 DNS、Fake-IP 排除域名，以及完整的 DNS 覆盖 JSON。`nameserver-policy`、`fallback-filter` 等嵌套规则会递归合并，其他字段保留。
- 删除 JSON 中的某个键，或将其设置为 `null`，可恢复该字段跟随订阅。点击「恢复跟随订阅」并保存，可以移除全部全局 DNS 覆盖。
- TUN 开启时最终配置会强制启用 DNS，即使自定义的 `enable` 为 `false`。页面明确提示这一约束。

修改保留在本地草稿中，点击「保存并应用」后才生效。保存失败时保留草稿和错误信息；关闭有修改的窗口时会提示是否放弃。核心未运行时可以保存通过校验的配置，启动核心后生效。

## 配置与运行链路

全局 DNS 覆盖存放在已有的 `clash-guard-overrides.yaml` 的 `dns-overrides` 字段中，不写入订阅源文件。生成配置的顺序为订阅与增强脚本 → 全局 DNS 覆盖 → TUN 必需配置。切换或更新订阅仍会应用全局覆盖。

`get_dns_settings` 返回持久化覆盖、已提交运行配置中的 DNS 和核心运行状态。`set_dns_settings` 校验数据类型、生成配置、调用当前核心的配置校验、保存并加载，通过后提交状态。失败时尝试恢复覆盖文件、运行配置和运行中的核心；恢复失败会一并返回错误。

核心配置加载复用 `CoreManager::load_generated_config`，避免再次执行增强脚本。核心启动和加载成功后提交 runtime 状态。前端响应配置变更事件，并每 10 秒刷新可见页面的状态。

## 启动与验证

使用 `./start.sh --desktop` 启动桌面开发应用，`./stop.sh --desktop` 停止。
网页预览使用 `NYANPASU_WEB_PORT=3017 ./start.sh --web`，结束后使用 `./stop.sh --web`；预览页不会实际保存 DNS 配置。

本次验证通过前端 TypeScript、修改文件的 ESLint/Prettier、Vite 生产构建、完整 Rust Windows GNU 目标 `cargo check` 和 DNS 模块的合并/类型校验测试。浏览器在 1440 px 与 390 px 宽度验证了表单、多行输入、非法 JSON、失败保留草稿、成功反馈、恢复继承和退出确认；保存相关交互使用测试 IPC。

Linux 桌面构建所需 GTK/GLib/WebKit 开发包已就绪。真实 DNS 编辑与加载需要在已安装桌面客户端中验证；浏览器的测试 IPC 结果不等同于实际内核应用验收。
